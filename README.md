# badawrite

[웹사이트 바로 열기](https://hwanghj09.github.io/badawrite/) · [배포 상태와 실행](https://github.com/hwanghj09/badawrite/actions/workflows/deploy.yml)

여러 PDF·사진·TXT·직접 입력한 영어 대본을 파일별 듣기 WAV로 변환하는 브라우저 앱입니다. API 키나 서버 저장소가 필요하지 않습니다. 전체 파일을 순서대로 생성하고 개별 WAV 또는 ZIP으로 저장합니다.

## 실행

Node.js 22.13 이상에서 `npm ci`, `npm run dev`를 실행한 후 `/badawrite/` 주소를 엽니다. `npm test`는 대본 분리·화자 구분·해설 제외·WAV 헤더를 검증하며, `npm run build`는 정적 배포용 `dist/`를 만듭니다.

## 공개 배포

`main` 브랜치에 푸시하면 GitHub Actions가 테스트·빌드 후 GitHub Pages에 자동 배포합니다. Actions의 `Deploy badawrite`는 수동 실행도 가능하며, 성공한 실행의 Summary와 `github-pages` 환경에 웹사이트 바로가기 링크가 표시됩니다. 별도 API 키나 GitHub 저장소 시크릿이 필요하지 않습니다. 사이트는 빈 상태로 시작하고 사용자가 올린 대본만 처리합니다.

## 사용법

1. PDF/JPG/PNG/WEBP/TXT를 동시에 선택하거나 끌어다 놓습니다. 최대 20개, 파일당 20MB, PDF당 100쪽입니다. PDF는 텍스트를 먼저 추출하며, 텍스트가 없는 스캔 페이지는 OCR을 사용합니다. 클립보드 사진 붙여넣기와 여러 직접입력 파일 추가도 가능합니다.
2. 파일 목록에서 각 대본을 확인합니다. 파일명·문항·답안·음성은 파일별로 분리합니다. `1.`, `1번`, `[16~17]`, `16번과 17번` 등으로 지문을 구분하며 `M:`/`W:`의 남녀 화자를 유지합니다. 줄이 바뀌어 이어지는 대사는 같은 화자가 읽습니다. 화자 표시가 없는 영어는 여자 화자에게 배정됩니다. 해석·해설과 안내방송·페이지 번호는 음성에서 제외합니다.
3. 파일을 올린 뒤 ‘듣기 만들기’를 누르면 예상 전체 듣기 길이와 자동 시작까지의 시간을 표시합니다. 첫 두 문항의 실제 생성 속도를 측정하고, 각 문항이 재생될 차례 전에 완성될지 계산해 충분히 준비되면 자동으로 이어 재생합니다. 기기가 느리면 더 모아서 시작하고 빠르면 일부만 준비된 상태에서 시작합니다. ‘지금부터 이어 듣기’나 문항 번호를 누르면 기다리지 않고 들을 수 있고, ‘자동 시작 취소’로 생성은 계속하면서 자동 재생만 끌 수 있습니다. 생성 시작부터 ‘문항별 바로 듣기’에서 각 번호의 상태와 준비된 문항 수를 볼 수 있습니다. 1~12번을 함께 생성해도 1번이 완성되면 ‘1번 · 듣기’를 바로 누를 수 있고 나머지 번호는 계속 생성됩니다. 다음 문항이 아직 준비 중이면 기다렸다가 이어서 재생하며, 브라우저가 자동 재생을 막아도 완료된 번호를 직접 눌러 들을 수 있습니다. 16~17번 공통 지문은 자동으로 두 번 재생합니다. 문항 시작 차임벨·간격·전체 문항 반복은 기본적으로 접혀 있는 ‘간격·안내방송 설정’에서 바꿀 수 있습니다. 완료된 문항은 ‘듣기’, 아직 생성 중인 문항은 ‘대기’로 표시합니다. 취소해도 완성된 문항은 남고, 전체 파일이 완성되면 WAV로 저장합니다. 재생 속도는 플레이어에서 조절하며 저장 파일은 원래 생성 속도를 유지합니다.
4. `①`~`⑤`로 시작하는 선택지와 `정답: ③`이 포함되면 선택·채점할 수 있습니다. 정답이 없으면 답만 기록하고 자동 채점하지 않습니다.
5. 전체 음성 생성 후 파일별 WAV 버튼이나 ZIP 저장을 누릅니다. 같은 파일명도 ZIP에서 덮어쓰지 않습니다. 읽기·생성 실패는 해당 파일에 표시하고 다른 파일은 계속 처리합니다. 취소해도 완료된 파일은 보존합니다. 대본·생성 설정을 바꾸면 영향을 받는 음성은 다시 생성해야 합니다.

모의고사 외에 영어 기사·이야기·교재 지문·인터뷰·회화 대본도 사용할 수 있습니다. 번호와 화자 표시가 없는 글은 빈 줄로 나눈 문단별로 생성해 준비된 문단부터 들려줍니다. 줄바꿈만 있는 문장은 같은 문단으로 이어 읽습니다. 이름이나 역할을 쓴 대화는 `Alice: Hello.`, `Bob: Hi.`, `Teacher: Welcome.`, `Student: Thank you.`, `A:`, `B:`, `Speaker 1:`처럼 화자마다 줄을 바꿔 주세요. 이름표는 읽지 않고 대본 화면에 표시하며, 이름·역할에는 등장 순서대로 두 음성을 번갈아 배정합니다. 이름만으로 성별을 판단하지 않으며 같은 이름은 파일 안에서 같은 음성을 유지합니다. 일반 지문에는 문제나 선택지가 없어도 됩니다.

## 실제 지원 범위

문제지를 함께 사용할 때는 대본 아래 **문제지 연결 · 한국어 질문도 읽기**를 열고 PDF·사진·TXT를 올리거나 번호가 있는 질문을 붙여 넣습니다. 듣기 1~17번의 **문제 문구만** 추출해 현재 선택한 대본과 같은 번호로 연결합니다. 선지·표·그림 속 문자·쪽 번호·머리말·전체 시험 안내·18번 이후 독해는 제외합니다. 16~17번 공통 질문은 별도로 유지합니다. 추출 문구와 연결 수를 확인하고 직접 수정할 수 있습니다. 고유명사·부정 표현 등 OCR 오타까지 자동으로 보장하지 않으므로 원본과 대조해 주세요. 일반 문항은 한국어 질문을 한 번 읽은 뒤 영어 대화를 재생합니다. 16~17번의 개별 질문은 지문을 두 번 들려준 뒤 읽으며, 이 순서는 개별 WAV와 ZIP에도 포함됩니다. 두 번 듣기는 영어 지문에만 적용합니다. 연결 해제·질문 수정 후에는 음성을 다시 생성해야 합니다. 파일별 문제지는 현재 탭에만 보관됩니다.

한국어 음성은 기기에서 실행하는 [Supertonic 2](https://huggingface.co/onnx-community/Supertonic-TTS-2-ONNX)를 사용하며 [OpenRAIL-M 라이선스](https://huggingface.co/Supertone/supertonic-2/blob/main/LICENSE)가 적용됩니다. 질문을 연결하거나 16~17번 안내를 생성할 때 처음 한 번 약 263MB의 한국어 모델을 추가로 내려받습니다. 질문은 외부 서버로 전송하지 않습니다. OCR이 문항 번호나 부정 표현을 잘못 읽을 수 있으니 생성 전에 확인하세요. 질문은 문항당 1,000자, 파일당 8,000자까지 지원합니다.

- PDF.js, Tesseract.js의 영어·한국어 OCR과 Kokoro의 미국 영어 남녀 합성 음성을 사용합니다. 영어 대화는 원본 성우를 복제하지 않습니다.
- 기본으로 평가원 2026학년도 수능 원본에서 편집한 시작 안내방송과 문항 시작 차임벨을 붙입니다. 차임벨은 한국어 질문보다 먼저 한 번 울리며, 대본 맨 앞의 `[Chime bell rings.]`와 중복하지 않습니다. 대화 중간의 차임벨 지시는 유지합니다. 두 번 듣기에서도 지문 시작 차임벨은 한 번만 울립니다. 16~17번은 두 번째 지문 뒤 개별 질문 앞에 차임벨이 각각 한 번 더 울립니다. 문항별 바로 듣기·듣고 풀기·WAV·ZIP은 같은 음성을 사용합니다. 고정 학년도·문항 수·반복 횟수 안내는 제외했습니다. ‘간격·안내방송 설정’에서 끄면 안내방송 없이 기존 합성 차임벨을 사용합니다. [음원 출처와 편집 구간](public/audio/README.md)을 확인할 수 있습니다. `[Pause]`는 0.8초의 쉼으로, `(10 seconds)` 같은 대기 시간은 기본 문항 간격보다 우선하여 처리합니다. 지원하지 않는 효과음은 화면에 안내하고 읽지 않습니다.
- 처음 OCR·음성 생성을 실행할 때 외부 CDN/Hugging Face에서 모델을 다운로드합니다. 사진·대본은 서버로 전송하지 않습니다. 음성 모델 준비에는 수 분과 상당한 메모리가 필요할 수 있습니다. 최신 데스크톱 Chrome/Edge를 권장합니다. 아이패드(iPadOS의 데스크톱 표시 포함)·휴대기기·메모리가 적은 기기는 안정 모드를 자동 적용합니다. 이 모드에서는 영어 q8 CPU 모델·단일 코어·4MB 대사 캐시·최대 300만 픽셀 OCR을 사용합니다. 한국어 질문·안내가 있으면 별도 엔진에서 먼저 준비한 뒤 엔진을 종료하고 영어를 생성하여 두 모델을 동시에 메모리에 올리지 않습니다. 파일 완료 시 영어 엔진도 종료합니다. 저장 WAV에는 한국어 질문과 영어가 모두 포함되며, 실제 iPadOS의 탭 메모리 한도에 따라 긴 파일은 나눠야 할 수 있습니다.
- 짧은 문장은 묶어서 합성하고, 데스크톱의 같은 탭에서 만든 영어 대사는 최대 64MB까지 재사용합니다. 안정 모드에서는 같은 파일 생성 중 최대 4MB를 재사용하며, 완료 후 엔진을 종료하므로 다음 파일이나 재생성에서는 모델을 다시 준비합니다. 간격·두 번 듣기 설정을 바꿔도 캐시에 남은 대사는 다시 합성하지 않습니다. 완료된 파일은 다음 생성에서 건너뜁니다. 대본을 고치면 바뀐 내용으로 다시 생성하며, 취소·새로고침으로 음성 엔진이 종료되면 대사 캐시는 사라집니다.
- 문항이 완성될 때마다 WAV로 바꾸고 원본 PCM 참조를 해제합니다. 마지막에는 문항별 WAV의 데이터를 Blob으로 연결하므로 전체 PCM과 완성 WAV를 동시에 큰 배열로 복사하지 않습니다. GPU 가속과 기존 음질 설정은 유지합니다.
- 사용 가능한 GPU가 있으면 WebGPU로 음성을 생성하고, 지원하지 않거나 실행에 실패하면 CPU로 자동 전환합니다. GPU용 모델은 CPU용보다 커서 첫 다운로드가 더 오래 걸릴 수 있지만 이후에는 브라우저 캐시를 재사용합니다. CPU는 브라우저에서 허용하는 경우 최대 4코어를 사용하며, 안정 모드는 GPU를 사용하지 않고 1코어로 실행합니다. GitHub Pages에서도 병렬 실행을 사용할 수 있도록 첫 방문 때 앱을 시작하기 전에 한 번 새로고침할 수 있습니다. 서비스 워커·격리 실행이 차단된 브라우저나 외부 사이트에 삽입된 화면은 단일 코어로 실행합니다. 기기별 실제 생성 속도는 다릅니다.
- 복잡한 다단 편집·흐린 사진의 OCR, 문항 구조·화자 인식은 틀릴 수 있습니다. 영어 대본만 잘라 올린 뒤 반드시 결과를 확인하세요. 한 번의 음성 생성은 영어 25,000자로 제한합니다.
- 가운데 구분선이 있는 두 단 스캔은 왼쪽 단부터 나눠 읽습니다. 스캔 답지의 화자 표시와 한글 해석 경계를 이용해 듣기 대본을 추출하지만, 원본 상태에 따라 단어나 화자를 잘못 읽을 수 있습니다.
- 파일, 대본, 답안, 생성 음성은 현재 탭 메모리에만 있습니다. 새로고침·탭 종료 전에 대본을 별도 보관하고 WAV나 ZIP을 저장하세요. 긴 파일 여러 개를 변환할 때는 메모리와 생성 시간이 많이 필요합니다.
- 16~17번 공통 지문은 자동으로 두 번 재생합니다. `다시 한 번 듣겠습니다`와 동일 지문이 이미 대본에 적힌 경우 한 번만 합성해 두 번 재생하므로, 전체 두 번 듣기 옵션을 켜도 네 번으로 중복되지 않습니다.

Kokoro와 Tesseract.js 및 그 모델의 각 라이선스가 적용됩니다. 모델·런타임 제공처에 연결할 수 없는 환경에서는 OCR/생성이 실패할 수 있습니다.

## 기기별 실행·문제 문구 회귀 검증

`npm test`는 iPad 데스크톱 UA·터치 정보와 저메모리 기기의 단일 코어/q8 선택, 제공된 디아카이브01 스캔의 실제 OCR 결과에서 선지·공통 안내·표·독해를 제외하는 처리를 검증합니다. `tests/fixtures/diarchive01-prompts.txt`는 원본을 눈으로 대조한 문제 문구입니다. 스캔 OCR 결과를 정답 문구로 하드코딩하지 않으며, 의심스러운 단어나 부정 표현은 원본을 확인해야 합니다.

실제 브라우저의 안정 모드 엔진 순서·취소·실패 전환 회귀 검증은 production preview를 켠 뒤 `python tests/browser-memory.py`로 실행합니다(Python Playwright와 `/usr/bin/chromium` 필요). 이 테스트의 음성 엔진은 대역이며 실제 모델 다운로드와 iPad 실기기 검증을 대체하지 않습니다.

## 이어 듣기 준비 시간

남은 전체 생성 시간뿐 아니라 각 문항의 준비 마감 시간을 검사합니다. 최근 생성 속도 중 느린 측정값에 30% 여유를 더하고, 아직 만들어지지 않은 지문의 예상 재생 시간은 짧게 잡아 시작 대기를 계산합니다. 완성된 문항은 실제 WAV 길이를 사용합니다. 한국어 질문·차임벨·간격·반복·재생 배속을 반영하며 15분으로 강제로 늘리지는 않습니다. 기기 속도나 탭 상태가 바뀌면 중간 대기가 생길 수 있습니다. 여러 파일은 파일별로 시작 준비를 계산합니다. 브라우저가 자동 재생을 막으면 ‘지금부터 이어 듣기’나 재생 버튼을 누르세요.

`npm test`는 약 15분 분량의 빠른/느린 생성·문항별 마감 시간·배속·중단된 생성과 차임벨/반복/WAV 일치를 검증합니다. production preview 실행 후 `python tests/browser-listening.py`는 자동 대기·수동 시작·취소·320px 화면을 검증합니다(음성 Worker 대역 사용).

## 문제 문구의 자주 틀리는 OCR 보정

문제지 추출·문구 미리보기·한국어 음성 생성 전에 `src/question-corrections.js`의 치환 규칙을 적용합니다. 별도 모델이나 서버 요청은 추가하지 않습니다. 입력한 영어 대본과 선지에는 적용하지 않습니다.

| 인식 예 | 보정 | 적용 범위 |
|---|---|---|
| 적절핫, 저절한, 저청한, 정청한, 적절찬 | 적절한 | 독립된 단어 또는 질문의 정형 문구 |
| 기장 적절한 | 가장 적절한 | `것을/것은`을 묻는 문구 |
| 적정한, 적절할 | 적절한 | 목적·의견·요지·주제·응답을 묻는 고정 문구 안에서만 |
| 옹답, 옹담, 응담 | 응답 | `남자/여자의 …으로 가장` 문맥 |
| 남지가 하는 말, 하는 맡의 목적 | 남자가 하는 말, 하는 말의 목적 | 해당 질문 문맥 |
| 말의 요기로/유지로, 여자의 의건으로 | 말의 요지로, 여자의 의견으로 | 뒤에 `가장`이 이어지는 질문 문맥 |
| 것을 르시오 | 것을 고르시오 | 질문 끝의 지시 문구 |

첨부 스캔의 여러 OCR 조건과 사용자가 제시한 오독을 기준으로 규칙을 정했습니다. 이 스캔에 없던 문서까지 정확도를 보장하지 않습니다. 숫자·영문 고유명사·부정 표현을 추측해서 바꾸지 않으며 `50`, `아넌`, 손상된 이름 등 불확실한 인식은 원본 대조가 필요합니다. 올바른 `적정한 가격`이나 일반적인 `가장 적정한 것은?`은 유지합니다.

`tests/question-corrections.test.js`는 실제 OCR 예시·여러 오류의 조합·반복 보정의 안정성·정상 문구 보존·음성 전달을 검증합니다. production preview에서 `python tests/browser-corrections.py`는 업로드→편집 문구→한국어 엔진 준비까지 검사합니다(음성 Worker 대역 사용).

## 최종 WAV·ZIP의 안내음 검사

기본 설정은 수능 시작 안내와 문항 시작 차임벨을 모두 포함합니다. 새 앱을 열 때 이전 페이지에서 브라우저가 복원한 체크박스 값은 HTML 기본값으로 초기화하며, 앱을 연 뒤 사용자가 직접 끈 설정은 존중합니다.

완성 파일을 저장하기 전에 각 문항 WAV의 실제 오디오를 검사합니다. 첫 문항의 시작 안내와 문항별 시작 차임벨이 빠졌으면 원본 음원을 보충하고, 이미 들어 있으면 중복하지 않습니다. 실제 WAV 길이로 문항 이동 위치와 전체 길이도 다시 계산합니다. 긴 PCM 전체를 새 배열로 복사하지 않고 Blob 조각을 연결하며, 안내음은 생성 시작 때 미리 불러와 네트워크가 끊겨도 저장할 때 다시 받을 필요가 없게 합니다.

플레이어 아래 **저장 WAV·ZIP: 시작 안내 포함 · 문항 시작 차임벨 포함** 표시로 저장 파일의 구성을 확인할 수 있습니다. 파일별 WAV와 ZIP 안의 WAV는 동일합니다. 이전에 내려받은 파일은 바뀌지 않으므로 업데이트된 앱에서 다시 생성·저장하세요.

`tests/final-recording.test.js`는 빠진 안내/차임벨의 복원, 기존 음원 중복 방지, 문항 위치, 원본 PCM 반올림 호환, ZIP 내용, 손상 파일·취소를 검사합니다. `python tests/browser-export.py`는 음성 Worker가 모든 안내음을 누락하도록 만든 뒤 실제로 내려받은 두 WAV와 ZIP의 안내/차임벨 PCM을 원본과 비교합니다(음성 Worker만 대역, 정적 음원과 저장 파일은 실제 데이터).

## 문항 번호 낭독

음성 엔진에 문항 번호를 숫자 대신 한글 독음으로 전달합니다. `10번 → 십번`, `11번 → 십일번`, `16~17번 → 십육번과 십칠번`으로 고정하여 횟수처럼 ‘열 번’으로 읽히는 것을 방지합니다. 화면·문항 연결·재생 위치의 번호는 숫자로 유지하며, 질문 본문의 수량·금액 등은 바꾸지 않습니다. 이 처리는 안정 모드와 일반 모드, 미리 듣기와 최종 WAV·ZIP에 동일하게 적용됩니다. 이미 만든 음성은 다시 생성해야 적용됩니다.


## 16~17번 안내와 질문 순서

[2026학년도 평가원 대본](https://www.suneung.re.kr/boardCnts/fileDown.do?fileSeq=4a3fe87d815c0a29d963a6cd801ae6ae)과 [EBS 공식 배포 방송 대본](https://wdown.ebsi.co.kr/W61001/01exam/20151117/go2/ix4A2Dre_eng_scr.pdf)의 순서를 적용합니다.

1. “십육번부터 십칠번까지는 두 번 들려줍니다.”와 공통 지시문
2. 영어 지문 1회
3. “다시 한 번 듣겠습니다.”
4. 같은 영어 지문 2회차
5. 16번 질문과 풀이 시간
6. 17번 질문과 풀이 시간

개별 질문은 연결한 문제지 또는 대본의 16·17번 문구를 사용합니다. 없는 질문은 만들어 읽지 않습니다. 문제지를 연결하지 않아도 고정 안내는 한국어로 합성합니다. 시작 안내방송과 문항 시작 차임벨은 기존 설정에 따라 공통 지시문 앞에 들어가며, 지문을 다시 들려줄 때는 차임벨을 반복하지 않고, 두 번째 지문 뒤 16번·17번 질문 앞에 각각 차임벨을 넣습니다. 문항 시작 차임벨을 끄면 개별 질문 앞 차임벨도 끕니다. 전체 반복을 켜도 이 지문은 두 번만 재생합니다.

‘간격·안내방송 설정’의 **16·17번 질문별 풀이 시간**은 기본 12초이며 5·10·12·15·20초로 바꿀 수 있습니다. 대본에 각 질문의 `(7 seconds)` 같은 시간이 있으면 그 값을 우선합니다. 두 질문의 풀이 시간을 합쳐 지문 뒤에 한꺼번에 넣거나 마지막에 중복 추가하지 않습니다. 예상 듣기 길이와 자동 시작 대기 계산에도 안내·질문·풀이 시간을 반영합니다. 변경 전 음성은 다시 생성해야 적용됩니다.

`tests/shared-sequence.test.js`는 실제 PCM 순서·영어 두 번 재생·문항별 대기·미리 듣기/최종 WAV 일치를 검사합니다. production preview에서 `python tests/browser-shared.py`는 실제 한국어·영어 모델을 안정 모드로 차례로 실행하고, 내려받은 WAV에서 안내/질문의 위치·영어 지문 두 번의 오디오 일치·질문별 기본 12초·안내 앞뒤 1.5초·개별 질문 앞 원본 차임벨·ZIP 일치를 검사합니다. 모델 다운로드와 실행에 수 분이 걸릴 수 있으며 iPad 실기기의 메모리 한도 검증을 대체하지 않습니다.


## 2026학년도 수능 참고 간격

사용자가 지정한 [영어 듣기 영상](https://www.youtube.com/watch?v=vLn7NcSxnjQ)은 2026학년도 수능입니다. 유튜브 직접 재생 연결에 제한이 있어 같은 시험의 [평가원 원본 음원 ZIP](https://www.suneung.re.kr/boardCnts/fileDown.do?fileSeq=f669c9c11dbea2640c3e49b6caab63c3)을 대본과 대조하고 FFmpeg 무음 검출(-35dB)로 시간을 측정했습니다. 유튜브 업로드의 시작 시각이나 편집 상태까지 일치하는지는 검증하지 않았습니다.

| 구간 | 원본의 무음 측정 | 앱 기본 간격 |
|---|---|---|
| 16~17번 반복 안내 → 공통 지시문 | 약 1.39초 | 1.5초 |
| 공통 지시문 → 첫 지문 | 약 1.53초 | 1.5초 |
| 첫 지문 → 다시 듣기 안내 | 약 1.52초 | 1.5초 |
| 다시 듣기 안내 → 두 번째 지문 | 약 1.54초 | 1.5초 |
| 두 번째 지문 → 16번 질문 차임벨 | 약 1.02초 | 1초 뒤 차임벨 클립 |
| 16번 질문 → 다음 차임벨 | 약 12.07초 | 풀이 12초 뒤 차임벨 클립 |
| 17번 질문 → 원본 마침 차임벨 | 약 12.09초 | 풀이 12초 |
| 일반 문항의 마지막 무음 | 대체로 약 13~14초 | 문항 사이 기본 13초 |

앱의 차임벨 클립에는 앞뒤 여백도 들어 있어 실제 소리 시작까지는 그 여백이 더해집니다. 한국어 질문·공통 안내 뒤의 쉼도 1.5초로 맞췄습니다. 사용자 지정 문항 간격과 대본의 명시된 풀이 시간은 유지하며, 전체 반복으로 일반 문항을 다시 들을 때는 기존 3초 간격을 사용합니다. 원본의 전체 시작 방송·마침 방송·모든 효과음을 그대로 복제하지 않습니다. 합성 음성과 지문의 길이에 따라 전체 재생 시간은 달라지고, 이어 듣기 준비 계산은 변경된 간격과 차임벨을 포함합니다.

측정값은 `tests/fixtures/csat2026-timing.json`에 보관하며 `tests/shared-sequence.test.js`에서 실제 생성한 PCM의 구간 간격이 참고 측정값에 가깝고 사용자 지정 시간이 우선하는지 검증합니다.
